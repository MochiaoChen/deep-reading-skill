# 强力研读

把一本非虚构书「长」进大脑里，产出一份**日后可以取代原书**的笔记。

方法出自万维钢《万万没想到·用强力研读书》，在《如何阅读一本书》之上追求深度与效率：不是流程清单，是心法。

---

## 先记住这条铁律

> **笔记里的「心得」必须来自用户本人，你不能代写。**

分工：

| 你负责 | 用户负责 |
|---|---|
| 逻辑脉络（把书变薄） | 看法与质疑 |
| 亮点（把好故事捞出来） | 灵感与联想 |
| 联系（在已有笔记里检索） | 最终判断 |
| 体例与格式 | — |

读书的目的是提升自己的「思想内力」。摘要可以外包，内力不能。你把四要素全部代劳，用户得到的只是一份更长的书评。

**操作上**：③心得那一栏，你只**提问**、不填答案；用户答完你再誊写进笔记。用户明确说「你先写一版我来改」时可以给草稿，但每条必须标 `【待用户确认】`，用户没确认的不许留在成稿里。

---

## 两种模式，先确认走哪种

**模式一 · 陪读（默认，推荐）**
用户自己读，你当第二遍的笔杆子和提问者。用户读完一章 → 口述或粘贴要点 → 你追问、整理、检索联系。
产出的是内力。

**模式二 · 代读（用户把书直接给你）**
你读 PDF/EPUB/TXT，产出①脉络②亮点④联系，把③心得留成问题清单交给用户。
产出的是地图，不是内力。开工前用一句话说明这个差别，别默默降级。

拿到 PDF/EPUB 先跑工作流 C 拆成分章文件，**不要一次把整本书读进上下文**——
「读一章，记一章」既是方法要求，也是上下文预算的要求。

模式一和模式二可以混：用户读了一半读不下去，剩下的你来读并出问题清单。

---

## 什么时候**不要**用这个技能

阅读分三档：**为娱乐读 / 为信息读 / 为理解读**。只有第三档才值得强力研读。

不要启动的情况：
- 小说、教辅、考试辅导书、工具书查询
- 新闻、资讯、纯信息性材料——这类**读得越快越好**
- 用户只想要一句话摘要或一个具体答案
- 专业学术著作（《广义相对论》那种）——本方法面向的是写给非专业读者的非虚构书

拿不准这本书配不配读两遍，读 `references/triage.md`。

## 工作流 A：从零研读一本书

### Step 0 · 定位

在动笔前先答三个问题，写进笔记开头：

1. 这本书属于哪个领域？用户在这个领域读过什么？（决定读多快）
2. 用户想从这本书里得到什么？
3. 走模式一还是模式二？

### Step 1 · 第一遍：陷进去

正常通读，**不记笔记**。放松地欣赏作者的思想和故事。不追求快——值得时不时停下来想一想的书才是好书。

模式二下你也照做：先整本过一遍再动笔，不要边读边写。

> 一本好书只读两遍，而且**读完一遍马上读第二遍**。一遍不够，三遍浪费。

### Step 2 · 第二遍：跳出来，逐章记笔记

按原书章节划分笔记章节，**保留各章标题**。读一章，记一章。

每一章写四块：

**① 逻辑脉络** ——「作者这一章到底想说什么」
- 用**自己的话**写，不许抄原句
- 通常只有几句话，但这几句话往往散落在几十页里
- 作者用来举例的小故事在这一步**全部跳过**
- 判据：把脉络串起来能看出全书的系统吗？看不出就是没读懂

**② 亮点** ——脉络分析完，再把好故事捞回来
- 只捞真正让人拍案叫绝、一语惊醒梦中人的
- 捞就捞细节，别缩写成一句话
- **好笔记是不均匀分布的**。有的章三条亮点，有的章一条没有，这是对的
- 反面教材：Kindle 上大多数人划的重点都是段落首句或末句这种「总结句」——那是小学生找中心句，不是研读

**③ 心得** ——见上面的铁律，你只提问
提问方向（每章挑 2–4 个真正有张力的，别凑数）：
- 这个结论你信吗？哪里不信？
- 作者这个说法能不能再往前推一步？
- 这解决了你之前关心的哪个问题——哪怕看起来跟本书无关？
- 你手上有没有反例？

**④ 联系** ——这个问题别的书怎么说？
- 先在用户已有的笔记库里检索（`scripts/link_notes.py` 或直接 grep）
- 找共同点，更要找**不同点**：谁的证据更强？结论被后来的书推翻了吗？
- 用 `[[笔记名]]` 记链接，指向还不存在的笔记也没关系——那是待写清单

记完一章，这一章就可以扔了。

### Step 3 · 心得访谈

模式二下集中做：把各章的③问题清单一次性抛给用户，一轮一轮聊，聊出来的话**原样**誊进笔记（保留用户的语气，别润色成书面语）。

### Step 4 · 织网

全书记完后跑一遍 `scripts/link_notes.py`，更新库索引和反向链接。

如果发现同一个问题在三本以上的书里有不同结论——提醒用户：**这时候你已经和作者平等了，该写文章了。**

### Step 5 · 收尾检查

对着 `references/note-rubric.md` 自检。四条全过才算完：

- [ ] 每章的逻辑脉络都在，且是用自己的话写的
- [ ] 亮点带走了，且分布不均匀
- [ ] 心得来自用户，没有 `【待用户确认】` 残留
- [ ] 至少有一条指向其他书/文章的联系
- [ ] 笔记详到「不用翻原书」的程度

最后问自己：**如果这本书只能记住两个字，是哪两个？**写在笔记最上面。
（《卧底经济学》的答案是「稀缺」。豆瓣热门书评前四篇没有一篇提到它，它们记住的是「咖啡」——而星巴克卖咖啡是全书前四页的事。）

## 工作流 B：审查一份已有笔记

用户拿来一份旧笔记问「这笔记行不行」时：

1. 按 `references/note-rubric.md` 的四要素逐项打分（0–3 分）
2. 指出**最短的那块板**，只给一条修改建议，别列十条
3. 常见诊断：
   - 只有摘要概括 → 缺①，看不出脉络，等于没读懂
   - 通篇金句摘抄 → 缺①，记住了树木忘了森林
   - 均匀工整、每章字数差不多 → 缺②，这是交作业不是记笔记
   - 全是书里的话 → 缺③，你只是个复读机
   - 一本书自成孤岛 → 缺④，知识没有进网络

### 特别提醒：思维导图没用

网上流行用思维导图做读书笔记，**效果很差**。有实验让三组人读同一篇科学文章：A 组多读几遍，B 组画概念图，C 组花十分钟写一篇相关文章。一周后测试，C 组胜出，而**画概念图的 B 组甚至不如单纯多读几遍的 A 组**。

眼过千遍不如手过一遍。用户要求画思维导图时，可以画，但要告诉他这替代不了写笔记。

## 工作流 C：把 PDF / EPUB 拆成分章文本

```bash
python3 scripts/book_to_text.py 书.epub --toc              # 先看结构和字数
python3 scripts/book_to_text.py 书.pdf --split ./chapters  # 一章一个文件
```

`--toc` 先跑，它会告诉你这本书有几章、每章多少字——据此决定 Step 2 一次读几章。
`--split` 之后按文件逐章读，这是模式二的标准姿势。

**EPUB** 用标准库解析，会从 `nav.xhtml` / `toc.ncx` 取真实章节名。

**PDF** 优先调用系统里的 `pdftotext` / `mutool` / `pypdf` / `pdfminer` / `PyMuPDF`；
一个都没装时退回内置的纯标准库提取器（zlib + ToUnicode CMap）。内置提取器能处理
大多数含嵌入文本的 PDF，**包括中文 CID 字体**。

两种它处理不了的情况，脚本会明确报错而不是吐乱码：

- **字体没有 ToUnicode 表** → 报「可读字符仅 N%」，并给出三条出路
- **扫描版 PDF（纯图片）** → 报「没有提取到任何文字」

这两种情况的正确应对是：让用户 `brew install poppler` 或 `pip install pypdf`
（装完重跑即可自动生效），**或者直接用你自己的 Read 工具按页读这个 PDF**。
Read 工具不需要用户安装任何东西，是最稳的兜底——别忘了这条路。

## 工作流 D：导入电子书划线

电子阅读器最大的好处是能自动抽出批注和高亮。

```bash
python3 scripts/extract_highlights.py --list               # 哪些书有划线
python3 scripts/extract_highlights.py --source apple       # Apple Books
python3 scripts/extract_highlights.py "My Clippings.txt"   # Kindle
```

**Apple Books** 直接读本机标注库，不需要用户导出任何东西。能带出书名、作者、
划线原文、附注、**高亮颜色**和时间。不给任何参数时默认就走这条路。

读不到数据库时脚本会报出三个可能原因，其中最常见的是**终端没有「完全磁盘访问
权限」**——遇到这个报错，直接把系统设置的路径念给用户，别自己瞎试。

**Kindle** 认 `My Clippings.txt`（中英文版皆可），按书分组、自动去重（同一段反复
划线只留最完整的一条）。

有人用颜色编码（黄=事实、蓝=存疑……），`--style 黄` 可以只取某一色。

导入后**不要**直接当笔记交付——划线只是原料，还要过 Step 2 的四要素。

顺带提醒用户：**读电子书一定要多批注**，别浪费那无限的空白处。（费马当年要是读的
电子书，大概就不会因为「书页空白太小」而不写下证明了。）

## 工作流 E：维护笔记库

```bash
python3 scripts/link_notes.py ~/notes/reading --index        # 生成/更新 INDEX.md
python3 scripts/link_notes.py ~/notes/reading --backlinks    # 写入反向链接区
python3 scripts/link_notes.py ~/notes/reading --report       # 孤岛笔记、断链、待写清单
```

用户读到一个新课题后，会在接下来几天里反复撞见它（就像小时候学会一个成语后到处
看见它）。**撞见就整理进库**，这是笔记网络长起来的方式。

## 笔记体例

模板见 `assets/note-template.md`。硬性约定：

- 自己的话一律放进 `【】`，日后一眼分清哪些是书里的、哪些是自己的
- 章节结构与原书一一对应，保留原章标题
- 跨笔记引用用 `[[笔记名]]`
- 亮点保留原文时加引号并注明页码/位置

## 关于速度

强力研读要求慢。但很多著名读书人读得极快——因为他们读得多。

经济学家 Tyler Cowen 一晚上能看好几本书，他自己的解释是：

> The best way to read quickly is to read lots. And lots. And to have started a long time ago. Then maybe you know what is coming in the current book.

读同一领域的书必然越读越快，因为新东西越来越少，一眼就能看出这本书在这个领域里的位置和新贡献。

所以：**Step 0 的第一个问题（用户在这个领域读过什么）决定后面所有步骤的速度。**领域内第五本书的笔记，理应比第一本薄得多，也尖锐得多。

更多心法背景见 `references/method.md`。
